# Example run — synthetic data

**Nothing in this directory is a real observation.** There is no animal called
`A1`, and no variant listed here was measured in anything. It exists so you can
open FluLens and see a populated screen without running the pipeline first.

Do not cite it, and do not use it to sanity-check a result.

## What it is

A twelve-sample Flumina output directory, small enough to ship in the repository
(476 KB):

| | |
|---|---|
| samples | 12 — four animals (`A1`–`A4`) sampled on days 1, 3 and 5 |
| calls | 1,378 rows — 1,237 LoFreq, 141 GATK4 |
| products | all twelve, including spliced M2 / NEP / PA-X and frameshifted PB1-F2 |
| curated hits | 275 rows against Flumina's own curated site database |
| above consensus | 280 calls over 50% |

## What is real about it

The scaffolding — the part that has to stay in step with the pipeline:

- **`reference.fa` is Flumina's own reference**, copied unmodified.
- **`reference_gtf/` is generated by Flumina's `makeGTF.R`**, not written by hand.
- **Product, CDS and codon annotation comes from Flumina's `fluORFs.R`** — the same
  code the pipeline uses, so the splice junctions in M2, NEP and PA-X are the real
  ones and the column schema cannot drift from real output.

Only the calls themselves — which samples, which positions, which frequencies and
depths — are invented. `../tools/make_example_run.R` regenerates the whole
directory from a fixed seed if you want to check that claim.

## What it was built to exercise

Each of these is a control that would sit dead in a demo built from arbitrary data:

- **Both callers at one site.** GATK4 rows carry `af_type=genotype` with an AF of
  1.0 while LoFreq rows carry the fraction — 139 of them are reconciled at load.
  This is why the table has two rows per change at most sites.
- **Two GATK4-only calls**, at depth 4 and 6, with no LoFreq counterpart and so no
  read-level evidence. These are the *Cannot assess* verdict.
- **A failing library.** `A4`'s three samples have median depth 124–147, under
  FluLens's default QC threshold of 200, so they mark ✕ — while every LoFreq call
  still clears Flumina's own `min_depth` floor of 100. Zero LoFreq rows sit below
  it, exactly as real output.
- **Fewer calls in the thin library**, 51–58 against 114–156 elsewhere. Scaling
  depth alone would have left A4 with a full complement of variants, which is
  internally inconsistent in a way a reader would notice.
- **Absent segments.** `A4_D3` and `A4_D5` recovered 6 of 8, so the coverage
  strip's "absent" outline is reachable.
- **Strand skew** on ~12% of VCF records, which is what puts calls into *Treat with
  caution* in the trust panel.
- **Recurrent sites**, so the matrix shows columns of calls rather than a field of
  singletons.

## What it does not include

No FluMut markers and no WFABC selection results. Both sections handle their own
absence and tell you how to enable them, which is more useful than fabricated
marker biology in a public repository — a made-up resistance marker is exactly the
kind of thing that gets quoted back later as though it were real.

## Note on the reference

Flumina's reference uses bare segment names (`A_HA`, `A_NA`) with no subtype
suffix, so FluLens reports **HA/NA FluMut markers as unconfirmable** on this data.
That is the intended conservative behaviour — the subtype cannot be read from the
names, and an unconfirmable position is treated as a mismatch rather than a pass.
You will see that warning in the sidebar. It is correct.
