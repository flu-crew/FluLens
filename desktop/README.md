# FluLens desktop shell

A thin Tauri wrapper around `prototypes/flulens.html`. The app itself is
unchanged — this exists to remove three limits of running it in a browser.

**Why it exists**

- **The folder picker forgets.** In the browser the run directory has to be
  re-chosen every session, because a `File` handle cannot be persisted. The
  shell remembers the last directory and reopens it.
- **`file://` cannot fetch.** So the dev path needs a web server, which cannot
  read `~/Documents` under macOS TCC — the reason development has been running
  against a copy in a scratch directory rather than the real file.
- **Ranged BAM reads.** The browser path depends on the dev server honouring
  `Range`; native file reads have no such dependency.

**What it deliberately does NOT do**

No rewrite of the app. The shell provides the same `files` map of objects with
`.text()`, `.bytes(a,b)` and `.size()` that `devBootstrap` already fakes and the
directory picker builds for real — so every code path below it is the one that
already works. If this shim and the picker ever disagree, the shim is wrong.

**Build**

    cargo install tauri-cli --version "^2" --locked   # once
    cd desktop && cargo tauri build

Output: `target/release/bundle/macos/FluLens.app`. Drag it to `/Applications`.
`cargo` needs `. "$HOME/.cargo/env"` in `~/.zshrc` — rustup wrote to `~/.profile`,
which zsh does not read, and could not amend the root-owned `~/.bash_profile`.

**Four things about this build that cost time**

1. **The frontend is compiled into the binary.** Editing `prototypes/flulens.html`
   changes nothing the app displays, and neither does copying it into `dist/` by
   hand while the app is running. Every frontend change needs a rebuild. This was
   mistaken for an app bug once — the letters scheme rendering Zappo in the app
   while the browser correctly rendered ClustalX, from an embedded stale copy.
2. **`beforeBuildCommand` runs from the PROJECT ROOT**, the parent of this
   directory — not from here, where `tauri.conf.json` lives. Its paths therefore
   read `prototypes/…` and `desktop/dist/…` and that is deliberate. `frontendDist`
   on the line above it *is* relative to this file. Two adjacent keys, two
   different bases.
3. **`frontendDist` must hold nothing but the frontend.** It was `../prototypes`
   at first, which carries the `run` symlink to a 28 GB results tree; Tauri walks
   the directory to embed it and the build was SIGKILLed four times. It reads
   exactly like an OOM kill or a sandbox kill and is neither. With `dist/` it
   compiles in ~17 s.
4. **`bundle.active` must be true to get an icon.** With it false the build still
   produces a working binary, so nothing looks wrong — but there is no `.app`, and
   therefore no `Info.plist` and no Dock icon.

**Icon:** generated by `mkicon.py` (stdlib only — no PIL, ImageMagick or node on
this machine), then `cargo tauri icon icon.png` fans it out to `icons/`.

**Status:** built and running, 2026-08-03 — see the FluLens handoff.
